# แบบระบบ Shopee Clip V2

วันที่: 2026-11-11 · สถานะ: รอเจ้าของโปรเจกต์รีวิว

## 1. เป้าหมาย

วางลิงก์สินค้า Shopee แล้วได้คลิปแนวตั้ง 15–22 วินาที พร้อมแคปชันและแฮชแท็ก สำหรับลงช่อง Shopee Video
แนวคลิปคือ motion graphic ตามตัวอย่างที่อนุมัติแล้ว (`sample/v2_wow_sample.mp4`)

เกณฑ์ว่าสำเร็จ:

- วางลิงก์ 1 ครั้ง กดไม่เกิน 2 ครั้ง ได้ไฟล์ mp4 โดยไม่ต้องแก้อะไรด้วยมือ
- สินค้าที่มีแต่รูปจากร้านก็ได้คลิปครบทั้งคลิป
- คลิป 2 ตัวของสินค้าต่างกันต้องดูไม่เหมือนกัน (ฉาก สี ลำดับ ต่างกัน)
- เลือกผู้ให้บริการ AI ได้ทั้งแบบ API และแบบแพ็กเกจรายเดือน

## 2. สิ่งที่ตัดสินใจแล้ว

| เรื่อง | ข้อสรุป |
|---|---|
| แนวคลิป | motion graphic: สินค้าตัดพื้นหลัง ตัวหนังสือกระแทกตามเสียง ฉากสำเร็จรูป เสียงเอฟเฟกต์ |
| ที่มาของภาพ | คลิปดิบของผู้ใช้ (ถ้ามี) > วิดีโอของร้าน > รูปของร้าน |
| ดึงข้อมูล | ส่วนขยาย Chrome ในเบราว์เซอร์ที่ผู้ใช้ล็อกอินเอง ไม่ใช้ Affiliate API |
| เสียงพากย์ | เสียงโคลนผ่าน Gemini แบบเดียวกับ V1 |
| อัปโหลด | ผู้ใช้กดลงเอง ระบบจบที่ไฟล์ mp4 |
| ภาษา | แกนระบบเป็น Rust ส่วนเรนเดอร์ภาพเป็น Remotion (ดูข้อ 3) |

## 3. เรื่อง Rust กับความเร็ว

แกนระบบเขียนด้วย Rust ตามที่ขอ แต่ต้องบอกตรง ๆ ว่า Rust จะไม่ทำให้ได้คลิปเร็วขึ้น

เวลาต่อคลิปหมดไปกับ 3 อย่าง ซึ่งไม่ขึ้นกับภาษาของแกนระบบ:

| ขั้น | เวลา | ที่มา |
|---|---|---|
| เรนเดอร์ภาพ (Chromium + ffmpeg) | 2–3 นาทีต่อคลิป 20 วินาที | วัดจริงตอนทำตัวอย่างบนเครื่องนี้ |
| AI เขียนสคริปต์ | ราว 5–15 วินาที | ประมาณการ ยังไม่ได้วัด |
| สร้างเสียงพากย์ | ราว 10–20 วินาที | ประมาณการ ยังไม่ได้วัด |

ส่วนเรนเดอร์ต้องเป็น Remotion (React) ต่อไป เพราะฉากในตัวอย่างที่อนุมัติเขียนด้วย Remotion
ถ้าเขียนตัวเรนเดอร์ใหม่ด้วย Rust ล้วน ต้องสร้างเอนจินวาดภาพเคลื่อนไหวและจัดตัวอักษรไทยเองทั้งหมด ไม่คุ้ม

สิ่งที่ได้จาก Rust คือโปรแกรมไฟล์เดียวที่เปิดแล้วใช้ได้ กินแรมน้อย และเสถียรเมื่อรันคิวยาว
สิ่งที่เสียคือโค้ด TypeScript ของ V1 (เสียงโคลน, TTS) เอามาใช้ตรง ๆ ไม่ได้ ต้องเขียนเรียก API ใหม่ใน Rust

ทางเลือก: ถ้าอยากเสร็จเร็วสุด ให้แกนระบบเป็น Node ทั้งหมดและยกโค้ด V1 มาใช้ ความเร็วต่อคลิปเท่ากัน แบบระบบข้ออื่นไม่เปลี่ยน

## 4. ภาพรวม

```
[Chrome + ส่วนขยาย] --ข้อมูลสินค้า--> [แกนระบบ Rust: 127.0.0.1]
                                          |  คิวงาน ทีละคลิป
        ดึงไฟล์ -> กำกับ (AI) -> พากย์ -> จัดเวลา -> เรนเดอร์ -> ส่งออก
                                          |
                              [ตัวเรนเดอร์ Node + Remotion]
[หน้าเว็บหน้าเดียว] <--- สถานะงาน, ตั้งค่า, ดาวน์โหลด
```

มี 4 ส่วน แต่ละส่วนทำงานเดียว:

| ส่วน | โฟลเดอร์ | ทำอะไร | ภาษา |
|---|---|---|---|
| ส่วนขยาย Chrome | `ext/` | อ่านข้อมูลจากหน้าสินค้าที่เปิดอยู่ ส่งให้แกนระบบ | JavaScript |
| แกนระบบ | `app/` | รับงาน เดินงานทีละขั้น เรียก AI เก็บไฟล์ เสิร์ฟหน้าเว็บ | Rust (axum, tokio) |
| ตัวเรนเดอร์ | `render/` | รับ `props.json` คืน mp4 และตัดพื้นหลังรูป | Node + Remotion |
| หน้าเว็บ | `app/ui/` | วางลิงก์ ดูคิว ตั้งค่า ดาวน์โหลด | HTML + JS ธรรมดา |

## 5. การใช้งาน

1. เปิดโปรแกรม หน้าเว็บขึ้นที่ `http://127.0.0.1:<port>`
2. วางลิงก์สินค้า (ได้หลายลิงก์ บรรทัดละลิงก์) เลือกแนวสคริปต์หรือปล่อยให้สุ่ม
3. ระบบเปิดลิงก์ใน Chrome ของผู้ใช้ทีละแท็บ ส่วนขยายอ่านข้อมูลแล้วส่งกลับเอง
4. ถ้ามีคลิปดิบ ลากไฟล์ใส่การ์ดสินค้านั้นก่อนกด "สร้าง" (ไม่ใส่ก็ได้)
5. รอคิว ได้ mp4 แคปชัน และแฮชแท็ก กดดาวน์โหลดหรือเปิดโฟลเดอร์

ถ้า Shopee ขึ้นหน้ายืนยันตัวตนหรือ CAPTCHA ผู้ใช้ทำเองในแท็บนั้น ระบบรอและไม่พยายามข้าม

## 6. รายละเอียดแต่ละส่วน

### 6.1 ส่วนขยาย Chrome (`ext/`)

- Manifest V3 ทำงานเฉพาะบน `shopee.co.th`
- อ่านจากหน้าที่ผู้ใช้เปิด: ชื่อ ราคา ส่วนลด คะแนน ยอดขาย จุดเด่นในรายละเอียด ลิงก์รูป ลิงก์วิดีโอของร้าน และรีวิวข้อความสูงสุด 5 อัน
- ส่งไปที่ `POST /api/ingest` ของแกนระบบ พร้อมรหัสลับที่ตั้งตอนติดตั้ง
- ทำงานเองเมื่อแท็บถูกเปิดจากระบบ และมีปุ่มกดเองสำหรับหน้าที่ผู้ใช้เปิดเอง
- ข้อจำกัด: ถ้า Shopee เปลี่ยนโครงหน้าเว็บ ส่วนนี้ต้องแก้ตาม เป็นจุดที่เปราะที่สุดของระบบ

### 6.2 แกนระบบ (`app/`)

งานหนึ่งงานคือโฟลเดอร์เดียวบนดิสก์ ไม่มีฐานข้อมูล:

```
jobs/<id>/
  product.json   ข้อมูลจากส่วนขยาย
  assets/        รูป วิดีโอ รูปตัดพื้นหลัง คลิปดิบที่ย่อแล้ว
  plan.json      แผนฉากจาก AI
  audio/         เสียงพากย์ทีละประโยค
  props.json     สิ่งที่ส่งให้ตัวเรนเดอร์
  out.mp4, caption.txt, job.json (สถานะและข้อผิดพลาด)
```

ขั้นของงาน แต่ละขั้นเขียนผลลงดิสก์ ถ้าล้มกลางทางสั่งทำต่อจากขั้นที่ค้างได้:

| ขั้น | ทำอะไร | ถ้าล้ม |
|---|---|---|
| assets | ดาวน์โหลดรูปและวิดีโอ ตัดพื้นหลัง ย่อคลิปดิบเป็น 1080×1920 | รูปที่โหลดไม่ได้ข้ามไป ถ้าไม่เหลือรูปเลยงานล้มพร้อมเหตุผล |
| direct | ส่งข้อมูลให้ AI ได้แผนฉาก ตรวจกับ schema และรายการคำต้องห้าม | ผิด schema ให้ AI แก้ 1 รอบ ถ้ายังผิดสลับไปผู้ให้บริการสำรอง |
| voice | สร้างเสียงทีละประโยค เก็บแคชตามข้อความและเสียง | ลองซ้ำ 2 ครั้ง แล้วสลับไปเสียงสำรอง |
| timeline | วัดความยาวไฟล์เสียงแต่ละประโยค คำนวณเฟรมของทุกฉาก | ไม่มีส่วนที่ล้มได้จากภายนอก |
| render | เรียกตัวเรนเดอร์เป็นโปรเซสแยก | เก็บ log ไว้ใน `job.json` ให้กดทำซ้ำได้ |
| export | เขียนแคปชัน แฮชแท็ก และคัดลอกไฟล์ไปโฟลเดอร์ส่งออก | — |

คิวทำทีละงาน เพราะการเรนเดอร์ใช้ CPU เต็มอยู่แล้ว

ความปลอดภัย:

- เซิร์ฟเวอร์ผูกกับ `127.0.0.1` เท่านั้น
- `/api/ingest` รับเฉพาะคำขอที่มีรหัสลับตรงกัน กันเว็บอื่นยิงข้อมูลเข้ามา
- ดาวน์โหลดไฟล์เฉพาะจากโดเมนรูปและวิดีโอของ Shopee ที่กำหนดไว้
- คีย์ API เก็บใน `config.toml` ในเครื่องเป็นข้อความธรรมดา (เหมือน `.env.local` ของ V1) ไม่ส่งออกไปที่อื่นนอกจากผู้ให้บริการของคีย์นั้น

### 6.3 ผู้ให้บริการ AI

งานที่ใช้ AI มี 2 อย่าง ตั้งค่าแยกกัน:

**ก. ผู้กำกับ (เขียนสคริปต์และเลือกฉาก)** เป็นงานข้อความ เลือกได้ 6 ทาง:

| ผู้ให้บริการ | แบบ API (จ่ายตามใช้) | แบบแพ็กเกจรายเดือน |
|---|---|---|
| Gemini | ใส่ API key | เรียกผ่าน Gemini CLI ที่ล็อกอินบัญชี Google ไว้ (เครื่องนี้มีแล้ว v0.54.4) |
| Claude | ใส่ API key | เรียกผ่าน Claude Code CLI ที่ล็อกอินไว้ (เครื่องนี้ยังไม่พบคำสั่ง `claude` ใน PATH) |
| GPT | ใส่ API key | เรียกผ่าน Codex CLI ที่ล็อกอินบัญชี ChatGPT ไว้ (เครื่องนี้มีแล้ว v0.165.0) |

- โค้ดมีอินเทอร์เฟซเดียว: ส่งข้อความเข้า ได้ JSON ออก ผู้ให้บริการแต่ละเจ้าเป็นตัวเสียบแยก
- ตั้งลำดับสำรองได้ เช่น "Claude รายเดือนก่อน ถ้าติดโควตาใช้ Gemini API"
- หน้าตั้งค่ามีปุ่ม "ทดสอบ" ของแต่ละทาง
- ข้อควรรู้ของแบบรายเดือน:
  - ทำงานโดยสั่งโปรแกรม CLI ของเจ้านั้นในเครื่อง จึงช้ากว่า API เล็กน้อย
  - โควตาใช้ร่วมกับการใช้งานปกติของบัญชี ถ้าทำคลิปเยอะอาจติดเพดาน
  - เงื่อนไขการใช้แพ็กเกจรายเดือนกับงานอัตโนมัติของแต่ละเจ้า ผมยังไม่ได้ตรวจ ผู้ใช้ควรเช็กก่อนใช้ปริมาณมาก

**ข. เสียงพากย์** มี 2 ทาง:

- Gemini เสียงโคลน (ค่าเริ่มต้น): ต้องใช้ Gemini API key เท่านั้น แพ็กเกจรายเดือนใช้กับส่วนนี้ไม่ได้ ใช้เสียงที่โคลนไว้แล้วใน V1 ได้เลยเพราะเก็บอยู่ที่บัญชี Google ของผู้ใช้
- Edge TTS เสียงไทยฟรี: เป็นตัวสำรองเมื่อ Gemini ล้มหรือโควตาหมด

ชื่อโมเดลและวิธีเรียกเสียงโคลนจะยกจากโค้ด V1 และทดสอบว่ายังเรียกได้ในขั้นแรกของการสร้าง

### 6.4 แผนฉาก (สัญญาระหว่าง AI กับตัวเรนเดอร์)

AI คืน JSON แบบนี้ แกนระบบตรวจก่อนใช้เสมอ:

```json
{
  "style": "problem-solution",
  "palette": "sky",
  "beats": [
    { "say": "นมผงชื้นจับเป็นก้อนอีกแล้วใช่ไหม", "scene": "hook",
      "text": ["นมผงชื้น", "จับเป็นก้อน?"], "media": "auto" },
    { "say": "กระปุกนี้ฝาซิลิโคนกันชื้น", "scene": "stamp",
      "text": ["กันชื้น"], "badges": ["ฝาซิลิโคน", "ล็อกแน่น"] },
    { "say": "พิกัดอยู่ในตะกร้าส้มเลย", "scene": "cta" }
  ],
  "caption": "…", "hashtags": ["…"]
}
```

กฎที่แกนระบบบังคับ:

- 6–9 จังหวะ รวมเสียงพากย์ 15–22 วินาที
- จังหวะแรกเป็น `hook` จังหวะสุดท้ายเป็น `cta`
- ฉากเดียวกันห้ามติดกัน
- ข้อความบนจอต่อบรรทัดยาวไม่เกินที่ฉากนั้นรับได้
- ตัวเลขและคำอ้างต้องมาจาก `product.json` เท่านั้น
- ไม่มีคำในรายการคำต้องห้าม (ยกไฟล์ `banned-claims.json` จาก V1)

### 6.5 ตัวเรนเดอร์ (`render/`)

ชุดฉากรุ่นแรก 10 แบบ ต่อยอดจากโค้ดตัวอย่าง:

| ฉาก | ใช้เมื่อ | ต้องมีคลิปไหม |
|---|---|---|
| `hook` | เปิดคลิป ข้อความกระแทก 2–3 บรรทัด | ไม่ (ใช้คลิปถ้ามี) |
| `hero` | โชว์สินค้าลอย ชื่อแบรนด์ตัวยักษ์ด้านหลัง | ไม่ |
| `bigword` | คำเดียวตัวยักษ์ทับภาพ | ไม่ (ใช้คลิปถ้ามี) |
| `grid` | แจก 3–4 ข้อ เด้งทีละช่อง | ไม่ |
| `stamp` | ตราประทับคุณสมบัติ 1–2 อัน | ไม่ |
| `count` | ตัวเลขวิ่ง เช่น จำนวนชิ้น ความจุ | ไม่ |
| `price` | ราคาเดิมขีดฆ่า ราคาใหม่กระแทก | ไม่ |
| `review` | ดาวและข้อความรีวิวจริง | ไม่ |
| `compare` | ก่อน/หลัง หรือ ปัญหา/ทางแก้ แบ่งจอ | ไม่ |
| `cta` | ปิดคลิป ชี้ตะกร้าส้ม | ไม่ |

- ทุกฉากรับความยาวเป็นจำนวนเฟรมจากภายนอก และจัดจังหวะภายในเองตามสัดส่วน
- ข้อความบนจอขึ้นตามเวลาที่ประมาณจากความยาวประโยค (สัดส่วนตามจำนวนตัวอักษร) ไม่ใช้ AI จับเวลา
- ความหลากหลาย: ชุดสี 5 ชุด ฟอนต์ 2 คู่ มุมเอียงและตำแหน่งสุ่มจากเลข seed ของงาน
- เสียงเอฟเฟกต์ผูกกับฉาก ไม่ต้องให้ AI สั่ง
- เพลงประกอบ: โฟลเดอร์ `bgm/` ที่ผู้ใช้ใส่ไฟล์เอง สุ่มเลือก ระบบไม่แจกเพลงให้เพราะเรื่องลิขสิทธิ์
- การตัดพื้นหลังใช้ไลบรารีเดียวกับ V1 รันในเครื่อง ถ้าผลตัดออกมาเล็กหรือว่างเกินเกณฑ์ ให้ใช้รูปเต็มในกรอบแทน

### 6.6 หน้าเว็บ

หน้าเดียว 3 ส่วน: ช่องวางลิงก์, รายการงานพร้อมสถานะแต่ละขั้นและปุ่มทำซ้ำ, หน้าตั้งค่า (ผู้ให้บริการ AI, เสียง, โฟลเดอร์ส่งออก)
ไม่มีตัวแก้สคริปต์หรือพรีวิวสดในรุ่นแรก ถ้าไม่ชอบผลให้กด "สร้างใหม่" ซึ่งสุ่มแนวและ seed ใหม่

## 7. การทดสอบ

- Rust: ทดสอบตัวตรวจแผนฉาก (กฎในข้อ 6.4 ทุกข้อ) และการคำนวณเฟรมจากความยาวเสียง
- ผู้ให้บริการ AI: มีตัวปลอมที่คืนแผนฉากตายตัว ใช้เดินงานทั้งสายโดยไม่เสียเงิน
- ตัวเรนเดอร์: เรนเดอร์ภาพนิ่ง 1 เฟรมต่อฉาก ต่อชุดสี เพื่อจับฉากที่พังหรือข้อความล้นจอ
- ทั้งสาย: สินค้าทดสอบ 2 ตัว (ทิชชู่เปียกที่มีคลิปดิบ และสินค้าที่มีแต่รูป) ต้องได้ mp4 ความยาว 15–22 วินาที

## 8. ลำดับการสร้าง

แต่ละช่วงจบด้วยของที่ผู้ใช้ลองได้จริง:

1. **ตัวเรนเดอร์**: ชุดฉาก 10 แบบ รับ `props.json` ที่เขียนด้วยมือ ได้ mp4
2. **แกนระบบ**: เดินงานทั้งสายจาก `product.json` ที่เขียนด้วยมือ รวมผู้ให้บริการ AI ทั้ง 6 ทางและเสียงโคลน
3. **ส่วนขยายและหน้าเว็บ**: วางลิงก์จริงแล้วได้คลิป
4. **ความหลากหลาย**: ชุดสี ฟอนต์ กฎสลับฉาก ทดสอบกับสินค้า 10 ตัว

## 9. ไม่ทำในรุ่นนี้

- อัปโหลดขึ้น Shopee Video อัตโนมัติ
- AI สร้างวิดีโอหรือรูปใหม่ (เช่น Veo)
- ตั้งเวลาทำงานล่วงหน้า หรือหลายผู้ใช้
- ตัวแก้สคริปต์และไทม์ไลน์ในหน้าเว็บ
- มาสคอตและธีมกระดาษของ V1
