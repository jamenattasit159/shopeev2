# แบบระบบ: โฆษณาแนวเล่าเรื่อง 3 มิติ (Story Ad)

วันที่: 2026-11-11 · สถานะ: รอเจ้าของโปรเจกต์รีวิว

## 1. เป้าหมาย

วางลิงก์สินค้า Shopee แล้วได้คลิปโฆษณาแนว "กฎเอาตัวรอด" แบบคลิปตัวอย่าง `story-ad/ad01-v1.mp4`
ความยาวไม่เกิน 60 วินาที ตัวละคร 3 มิติ พากย์ด้วยเสียงโคลน

เกณฑ์ว่าสำเร็จ:

- วางลิงก์แล้วระบบทำถึงคลิปฉบับร่างเองโดยไม่ถามระหว่างทาง
- คลิปฉบับร่างแสดงแยกเป็นฉาก เลือกฉากแล้วพิมพ์สิ่งที่อยากแก้ได้ ระบบแก้และเรนเดอร์ใหม่เฉพาะฉากนั้น
- กดยืนยันแล้วระบบรวมทุกฉากเป็นคลิปเดียวและส่งออก
- ทำคลิปที่สองของสินค้าคนละตัวได้โดยไม่ต้องมีคนเขียนโค้ด

## 3. ภาพรวม

```
[หน้า Story Ad ใน V2] --ลิงก์--> [ส่วนขยาย Chrome เดิม] --ข้อมูลสินค้า--> [แกนระบบ Rust เดิม]
        เตรียมรูป -> เขียนบท -> พากย์ -> จับเวลา -> วางช็อต -> ของเฉพาะคลิป -> เรนเดอร์ทีละฉาก
                                                                    |
        [หน้าตรวจ: แถบฉาก] <-- แก้เฉพาะฉาก --> เรนเดอร์ฉากนั้นใหม่ --> ยืนยัน --> รวม + ผสมเสียง + ส่งออก
```

ส่วนที่ใช้ของเดิม: ส่วนขยาย Chrome, คิวงาน, การตั้งค่า AI, การเตรียมรูปและตัดพื้นหลัง, หน้าแสดงขั้นตอน
ส่วนที่สร้างใหม่มี 4 ชิ้น:

| ชิ้น | โฟลเดอร์ | ทำอะไร |
|---|---|---|
| ตัวเรนเดอร์ 3 มิติ | `story/` | โปรเจกต์ Remotion + three.js ยกจากคลิปตัวอย่าง รับ `film.json` คืนวิดีโอทีละฉาก |
| คลังฉากและช็อต | `story/src/sets`, `story/src/shots` | ฉากสำเร็จรูปและมุมกล้องมาตรฐานที่ AI เลือกใช้ |
| สายงาน story | `app/src/story.rs` | ขั้นตอนของงานแนวนี้ในแกนระบบ Rust |
| หน้า Story Ad | `app/ui/story.*` | วางลิงก์ ดูคิว ตรวจทีละฉาก ยืนยันส่งออก |

## 4. แผนคลิป (`film.json`)

สิ่งเดียวที่ตัวเรนเดอร์อ่าน AI เขียน แกนระบบตรวจ และการแก้ฉากคือการแก้ไฟล์นี้เฉพาะส่วนของฉากนั้น

```json
{
  "set": "kitchen",
  "cast": { "you": "parent", "pet": "cat" },
  "scenes": [
    { "line": 1, "vo": "ถ้าลูกร้องหิว ตอนตีสอง อย่าเพิ่งตักนมผง จากกระป๋องที่เปิดไว้",
      "sub": "If your baby cries at 2 a.m., don't scoop from the open tin yet.",
      "cuts": [
        { "shot": "subject", "state": { "lid": "ajar" }, "card": { "type": "rule" } },
        { "shot": "face", "you": "sleepy" }
      ] }
  ]
}
```

- **ฉาก** = หนึ่งประโยคพากย์ มี 1–2 คัต หน่วยนี้คือหน่วยที่ตรวจและแก้
- **shot** เลือกจากคลัง: `subject` (ของสำคัญ), `subject-close`, `top` (มองลง), `face`, `wide`, `pet`, `pet-subject`, `product`, `product-open`, `photo` (รูปจริงจากร้าน), `price`
- **you / pet** เลือกท่าจากชุดสำเร็จ: `rest`, `sleepy`, `reach`, `dig`, `shock`, `relief` และ `stare`, `calm`, `sleep`
- **card**: `rule`, `tag`, `clock`, `proof`, `photo`, `price`, `end`
- **state** คือสถานะของของในฉาก แต่ละฉากประกาศเองว่ารับค่าอะไร

กฎที่แกนระบบบังคับก่อนพากย์:

- แถว 1 ขึ้นต้น "ถ้า" และมี "อย่า" และมีตัวเลขหรือเวลา
- มีแถวจุดเปลี่ยน (`turnRow`) ตามมุมเล่าที่ได้รับ (ข้อ 4.1) เฉพาะมุม "หักมุม" ที่ต้องเป็นแถว "คุณทำถูกทุกอย่าง ยกเว้นเรื่องเดียว"
- 12–16 แถว บทรวมไม่เกิน 620 ตัวอักษร (คลิปตัวอย่าง 676 ตัวอักษรได้ 57 วินาที)
- สินค้าเข้าหลังแถวจุดเปลี่ยน ราคาและคุณสมบัติต้องมีในข้อมูลสินค้า ถ้าหน้าสินค้าไม่มีราคา ห้ามพูดราคา
- ไม่มีคำต้องห้ามจากรายการของ V2 และไม่มีคำว่า "บัว"
- ข้อเท็จจริงที่มีตัวเลขและไม่ได้มาจากหน้าสินค้า ต้องติดป้าย "ยังไม่ได้ตรวจ" และแสดงเตือนในหน้าตรวจ
- shot, ท่า, card และ state ทุกค่าต้องมีอยู่ในคลัง

### 4.1 เส้นเรื่องต้องไม่ซ้ำ

ปัญหาที่เจอ: ทุกคลิปออกมาเป็นเรื่องเดียวกัน (ตีสอง ในครัว ชงนม ทำถูกทุกอย่างยกเว้นเรื่องเดียว) แม้สินค้าจะต่างกัน คนดูเบื่อเร็ว

หลักใหม่:

- **เรื่องเริ่มจากสินค้า ไม่ใช่จากแม่แบบ** AI ต้องตอบก่อนว่าสินค้าคืออะไร ใครใช้ ใช้ตอนไหน ปัญหาที่มันแก้คืออะไร (`productUse`) แล้วเลือกสถานการณ์ เวลา และตัวละครให้เข้ากับคำตอบนั้น ไม่ใช่ตีสองเสมอไป
- **มุมเล่ามีหลายแบบ** ระบบเลือกมุมเล่าให้แต่ละงาน และไม่ใช้มุมที่คลิปล่าสุดใช้ไปแล้ว:

| มุม | โครง | จุดเปลี่ยน |
|---|---|---|
| หักมุม | ทำตามขั้นตอนถูกหมด แต่ผลผิดเพราะรายละเอียดเดียวที่อยู่ในภาพตั้งแต่ต้น | แถว "คุณทำถูกทุกอย่าง ยกเว้นเรื่องเดียว" |
| ความเชื่อผิด | คนส่วนใหญ่เชื่อแบบหนึ่ง คุณก็ทำตาม แล้วเจอว่ามันผิด | แถวที่หักล้างความเชื่อ |
| นับถอยหลัง | เหตุการณ์มีเส้นตาย เวลาบนจอเดินเร็ว ทุกแถวกดดันขึ้น | แถวที่เวลาหมด หรือเกือบหมด |
| สัญญาณเตือนสามข้อ | สัญญาณเล็กๆ สามอย่างโผล่ทีละข้อ คุณมองข้ามสองข้อแรก | แถวที่ข้อที่สามโผล่ |
| สองทางเลือก | คืนเดียวกันเล่าสองแบบ แบบที่ทำตามสัญชาตญาณ กับแบบที่ทำตามกฎ | แถวที่เรื่องแยกเป็นสองทาง |
| สิ่งที่แมวเห็น | แมวรู้ก่อนตั้งแต่แรก คนดูเห็นตามสายตาแมว แต่คุณไม่เห็น | แถวที่คุณเห็นสิ่งที่แมวเห็นมาตลอด |

- **ห้ามซ้ำของเดิม** ระบบส่งชื่อเรื่อง กฎ และแถวแรกของคลิปล่าสุด (สูงสุด 8 คลิป) ไปให้ AI เพื่อห้ามใช้สถานการณ์ เวลา และกฎที่คล้ายกัน
- **ตรวจซ้ำ** หลังได้บท มี AI อีกรอบตรวจว่า (ก) ปัญหาเป็นสิ่งที่สินค้านี้แก้ได้ตรงๆ และ (ข) ไม่ซ้ำกับคลิปล่าสุด ถ้าไม่ผ่านให้เขียนใหม่ได้ 2 รอบ
- กฎแถว 1 ("ถ้า... อย่า...") ยังเป็นเอกลักษณ์ของช่อง ส่วนที่เปลี่ยนได้คือสถานการณ์ เวลา โครงกลางเรื่อง และจุดเปลี่ยน

## 5. คลังฉาก

รุ่นแรก 3 ฉาก ครอบคลุมของใช้ในบ้านซึ่งเป็นสินค้าส่วนใหญ่ของช่อง:

| ฉาก | ใช้กับ | ของสำคัญที่สลับสถานะได้ |
|---|---|---|
| `kitchen` (มีแล้วจากคลิปตัวอย่าง) | ของใช้ในครัว ของเด็ก อาหาร | กระป๋อง/ภาชนะ ฝา แก้ว |
| `bedroom` | เครื่องนอน ของใช้เด็ก ของช่วยนอน | เตียง โคมไฟ ของบนหัวเตียง |
| `bathroom` | ของใช้ส่วนตัว ทำความสะอาด | อ่าง กระจก ชั้นวาง |

ทุกฉากมีจุดอ้างอิงชุดเดียวกัน (ตำแหน่งคุณ สัตว์ ของสำคัญ สินค้า) มุมกล้องในคลังจึงใช้ได้กับทุกฉาก
ถ้าเรื่องไม่เข้ากับฉากไหนเลย AI ต้องเลือกฉากที่ใกล้สุดและแจ้งเตือนในหน้าตรวจ

## 6. ของเฉพาะคลิป (Claude เขียน)

สองอย่างที่คลังให้ไม่ได้ เพราะต่างกันทุกสินค้า:

- **โมเดลสินค้า 3 มิติ** ดูจากรูปสินค้าจริง
- **ของประกอบจุดหักมุม** เช่น ฝาที่เผยอ สายที่หลุด

วิธีทำงาน:

- แกนระบบสั่ง Claude Code แบบไม่มีหน้าจอ ให้เขียนไฟล์เดียว `custom.tsx` ในโฟลเดอร์งาน ตามรูปแบบที่กำหนดตายตัว
- ตรวจด้วยการคอมไพล์และเรนเดอร์ภาพนิ่ง 2 เฟรม
- ถ้าไม่ผ่านใน 2 รอบ ใช้ทางสำรอง: สินค้าแสดงเป็นรูปจริงในกรอบ และจุดหักมุมใช้ของในคลัง งานไม่ล้ม
- ต้องมี Claude Code ติดตั้งและล็อกอินในเครื่อง (เครื่องนี้มีที่ `C:\Users\DOL\.local\bin\claude.exe`) และใช้โควตาแพ็กเกจ Claude ของคุณ

## 8. หน้าตรวจและการแก้ทีละฉาก

- แถบฉากเรียงตามลำดับ แต่ละฉากมีภาพตัวอย่าง ปุ่มเล่นเฉพาะฉาก บทพากย์ และคำเตือนถ้ามี
- เลือกฉาก พิมพ์สิ่งที่อยากแก้เป็นภาษาคน เช่น "ให้แมวหันมามองกล้อง" หรือ "เปลี่ยนเป็นมุมกว้าง"
- ระบบส่งแผนของฉากนั้นกับคำสั่งให้ AI ได้แผนฉากใหม่ ตรวจตามกฎเดิม แล้วเรนเดอร์เฉพาะฉากนั้น ฉากอื่นไม่ถูกแตะ
- การแก้ 3 ระดับ:

| แก้อะไร | ระบบทำอะไร | เวลา |
|---|---|---|
| มุมกล้อง ท่า การ์ด ข้อความบนจอ | เรนเดอร์ฉากนั้นใหม่ | เร็ว |
| คำพูดของฉากนั้น | พากย์ใหม่เฉพาะประโยค แล้วเรนเดอร์ฉากนั้น | ปานกลาง |
| โมเดลสินค้าหรือของประกอบ | Claude แก้ `custom.tsx` แล้วเรนเดอร์ทุกฉากที่ใช้ของนั้น | ช้า |

- ถ้าพากย์ใหม่แล้วประโยคยาวขึ้นจนคลิปเกิน 60 วินาที ระบบแจ้งเตือนก่อนยืนยัน
- ปุ่ม "ยืนยันและส่งออก" รวมฉากและส่งไฟล์ไปโฟลเดอร์ส่งออกเดียวกับ V2

## 9. การทดสอบ

- Rust: กฎในข้อ 4 ทุกข้อ และการแทนที่แผนเฉพาะฉากโดยไม่กระทบฉากอื่น
- ตัวเรนเดอร์: `film.json` ของคลิปตัวอย่างต้องให้ภาพเหมือนคลิปที่ทำด้วยมือ และภาพนิ่ง 1 เฟรมต่อช็อตต่อฉากในคลัง
- ทั้งสาย: สินค้า 2 ตัว (กระปุกนมผงในครัว และมือตบกล่อมนอนในห้องนอน) ต้องได้คลิปไม่เกิน 60 วินาที
- แก้ฉาก: แก้ 1 ฉากแล้วไฟล์ของฉากอื่นต้องไม่เปลี่ยน

## 10. ลำดับการสร้าง

1. **ตัวเรนเดอร์จากแผน**: ย้ายโค้ดคลิปตัวอย่างมาเป็น `story/` ให้ขับด้วย `film.json` เรนเดอร์ทีละฉาก ต่อไฟล์ได้
2. **หน้าตรวจและแก้ทีละฉาก**: ทำกับ `film.json` ที่เขียนด้วยมือก่อน
3. **AI เขียนบทและแผนจากลิงก์**: รวมพากย์และจับเวลาอัตโนมัติ
4. **ของเฉพาะคลิปโดย Claude** และฉากห้องนอน ห้องน้ำ

จบช่วงที่ 2 คุณจะลองแก้ทีละฉากกับคลิปกระปุกนมผงได้แล้ว จบช่วงที่ 3 วางลิงก์แล้วได้คลิป (สินค้าเป็นรูปจริงในกรอบ)

## 11. ไม่ทำในรุ่นนี้

- ตัวละครขยับต่อเนื่อง (เดิน หยิบของ) ยังเป็นท่านิ่งต่อคัตเหมือนคลิปตัวอย่าง
- ซีรีส์หลายตอนและไบเบิล (ยังเป็นงานของ MotionStudio)
- ตัวละครมากกว่า 1 คนกับสัตว์ 1 ตัว
- ตรวจข้อเท็จจริงอัตโนมัติกับแหล่งข้อมูลภายนอก (ระบบแค่ติดป้ายให้คุณตรวจ)

## 12. ความเสี่ยง

| ความเสี่ยง | ผลกระทบ | วิธีรับมือ |
|---|---|---|
| คลิปหน้าตาคล้ายกันเพราะฉากมี 3 แบบ | คนดูเบื่อ ช่องดูซ้ำ | สลับสีผนัง แสง สัตว์ เสื้อผ้าตาม seed และเพิ่มฉากทีหลัง |
| โมเดลสินค้าที่ Claude เขียนไม่เหมือนของจริง | สินค้าดูผิด | มีรูปจริงตามหลังเสมอ และทางสำรองเป็นรูปในกรอบ |
| AI แต่งข้อเท็จจริง | ข้อมูลผิดในโฆษณา | กฎตัวเลขจากข้อมูลสินค้า และป้าย "ยังไม่ได้ตรวจ" ในหน้าตรวจ |
| เรื่องที่ AI แต่งไม่เข้ากับฉากในคลัง | ภาพไม่ตรงบท | บังคับ AI เลือกฉากก่อนแต่งเรื่อง และเตือนในหน้าตรวจ |
| เวลาต่อคลิปยาว | ทำได้น้อยคลิปต่อวัน | ยังไม่ได้วัด จะวัดจริงตอนจบช่วงที่ 1 |
| การจับเวลาต้องใช้ Python กับ faster-whisper | ติดตั้งเพิ่มบนเครื่องใหม่ | เครื่องนี้มีแล้ว ตรวจตอนเปิดโปรแกรมและแจ้งถ้าขาด |
